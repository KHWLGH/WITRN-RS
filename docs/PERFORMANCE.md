# 图表、UI 与数据存储性能优化报告

日期：2026-09-26。本文汇总已实施的 UI 更新控制、图表与统计分时处理、CSV Worker、PD 列表投影，以及 11 列原始数据的分块存储。原始采样点未降精度或删减；显示分桶只改变提交给图表的绘图顶点。

## 范围与基线

- UI 阶段：监控视图隐藏时推迟局部绘制和 DOM 更新，恢复时补齐显示；采样、统计与积分继续进行。避免未变化读数的重复 DOM 写入，并合并图表更新。该阶段的有窗口 Edge 测量受到帧供应节流，不据此计算 FPS 提升。
- 计算阶段：大范围统计、导航图冷准备、极值索引和大窗口投影分片执行；CSV 解析、稳定排序、统计和积分移入模块 Worker；PD 筛选及行布局分片并保持增量追加。光标仍指向最近的原始样本。
- 存储阶段：11 个连续、倍增扩容的 `Float64Array` 列改为每块 4096 点的列。录制前为整行预留空间，最后发布 X 列；图表、统计、CSV、积分都从块读取，稀疏窗口仅复制可见原始点及相邻点给 uPlot。

主要浏览器对照的“前”是 `bench/results/phase2-before/src`，即 UI 阶段之后、计算阶段之前的工作区源码快照；“后”是最终工作区。分块存储另与 `bench/results/phase3-before/src`（计算阶段之后、存储阶段之前）比较。这些基线**不是 Git HEAD**。原始 JSON 和源码快照位于按仓库规则忽略的 `bench/results/`，未纳入版本控制。

## 端到端浏览器对照

设备为 Intel Core Ultra 9 285H、Windows 10.0.26200、Node v24.18.0、Edge 154.0.4258.37。前后使用同一版 `bench/phase2-browser.mjs`、确定性数据、1280×800 视口和正式 CSP。每个规模独立页面，每项预热 2 次、计入 7 次。

“最大等待”是每次操作期间最大的定时器间隔，再取 7 次的中位数；它衡量主线程响应，不等同于 FPS。完成时间包含两边相同的约 20 ms 稳定等待。长任务数是这些运行中浏览器报告的至少 50 ms 任务数。单位均为 ms。

| 操作 | 最大等待中位数：前 → 后 | 完成时间中位数：前 → 后 | 长任务数：前 → 后 |
| --- | ---: | ---: | ---: |
| 100 万点图表冷准备 | 51.5 → 5.1 | 72.4 → 75.8 | 5 → 0 |
| 500 万点图表冷准备 | 235.3 → 5.0 | 255.1 → 257.3 | 7 → 0 |
| 100 万点大范围统计 | 11.8 → 5.0 | 11.6 → 17.7 | 0 → 0 |
| 500 万点大范围统计 | 55.5 → 5.0 | 55.4 → 80.2 | 7 → 0 |
| 10 万行 CSV 导入（100 万点页面） | 80.7 → 13.8 | 100.3 → 141.5 | 7 → 0 |
| 100 万条 PD 筛选与布局 | 95.4 → 5.2 | 117.1 → 101.7 | 7 → 0 |

主要收益是响应性：500 万点图表最大等待下降约 97.9%，大范围统计下降约 91.0%；这不表示所有操作完成得更快。500 万点统计总完成时间增加约 44.8%，CSV 导入增加约 41.1%。Worker 启动、分片调度及分块扫描各有成本。PD 在独立浏览器运行间波动较大，不把一次完成时间差归因于存储改造。

计算阶段单独测过核心算法：500 万点范围统计总耗时中位数为 55.70 → 48.99 ms，最长计算片段中位数为 55.70 → 1.53 ms；极值索引冷构建分别为 168.35 → 148.84 ms 和 168.35 → 1.78 ms。500 万点索引预留容量从 53,587,200 B 降至 40,038,784 B。分片预算是软预算，索引最长片段的 p95 仍达到 10.46 ms，不能承诺实时上限。这组数据来自 `bench/results/phase2-algorithms.json`，其前后对照是计算阶段开始前的工作区快照，与上面的端到端对照不同。

## 扩展规模测试与效果判断

新增测试沿用相同的旧源码快照、当前源码、Edge 版本和脚本，但每项预热 1 次、计入 5 次；前后顺序运行独立浏览器进程。下表均为中位数，`等待`表示操作期间最大的主线程定时器间隔，`耗时`表示操作完成时间，单位为 ms。小于约 5 ms 的等待接近测试所见的计时器基础间隔，不能据此推断更细的响应差异。

| 场景 | 等待：前 → 后 | 耗时：前 → 后 | 判断 |
| --- | ---: | ---: | --- |
| 1 万点图表冷准备 | 5.3 → 5.1 | 23.1 → 22.9 | 基本持平 |
| 10 万点图表冷准备 | 8.9 → 10.3 | 28.9 → 29.5 | 基本持平；未见稳定收益 |
| 100 万点图表冷准备 | 54.1 → 5.2 | 73.1 → 79.4 | 卡顿约降 90.4%，完成约慢 8.6% |
| 10 万点范围统计 | 6.0 → 4.9 | 1.5 → 4.5 | 总耗时增加；绝对值仍小 |
| 100 万点范围统计 | 14.9 → 5.3 | 14.8 → 21.4 | 卡顿约降 64.4%，完成约慢 44.6% |
| 1 万条 PD 筛选 | 5.0 → 5.1 | 25.1 → 25.4 | 基本持平 |
| 10 万条 PD 筛选 | 15.7 → 5.2 | 35.9 → 33.7 | 卡顿约降 66.9%；总耗时差较小 |
| 100 万条 PD 筛选 | 119.9 → 5.7 | 140.6 → 140.6 | 卡顿约降 95.2%；总耗时持平 |
| 1 万行 CSV 导入 | 13.4 → 9.3 | 32.0 → 65.2 | 响应略好，总耗时约翻倍 |
| 30 万行 CSV 导入 | 246.9 → 11.7 | 266.2 → 347.4 | 卡顿约降 95.3%，完成约慢 30.5% |

100 万点图表、100 万条 PD 和 30 万行 CSV 的浏览器长任务数分别为 5 → 0、5 → 0、5 → 0；1 万、10 万点场景原本就没有长任务。先前 500 万点对照仍显示图表卡顿约降 97.9%，但图表总耗时基本持平，统计总耗时增加约 44.8%。这说明收益随数据规模增大而明显增强，且集中在**主线程响应性**，并非所有操作的吞吐量都提高。1 万行 CSV 的 Worker 启动和传递开销相对工作量很大；30 万行时额外耗时占比缩小，但仍为实质性退步。

新增浏览器对照的图表各列哈希、统计标量、CSV 11 列哈希前后相同；PD 原始条目数、筛选计数与实时尾部校验通过，未见 CSP 违规或运行时异常。虚拟列表的滚动定位前后不同，因此可见 DOM 行不作为逐行等价证据。原始记录在 `bench/results/performance-expanded-before.json`、`performance-expanded-after.json`、`performance-csv300k-before.json` 和 `performance-csv300k-after.json`。这些结果是单机、少量重复的模拟浏览器测量；10 万点图表约 1 ms 的差、PD 完成时间的小幅差异都不宜解释为确定的性能变化。

**定性结论：**以“大数据量操作时界面不卡住、原始数据不丢失”为目标，优化幅度**大**，尤其是 100 万至 500 万点图表、百万条 PD 和大 CSV 导入。以“每个操作尽快完成”为目标，整体收益**小且不均匀**：图表和 PD 多数持平，范围统计及 CSV 导入变慢。综合评价是**响应性大幅改善，吞吐量有明确代价**；不能概括成整款软件所有场景都大幅加速。

## 分块存储的收益与代价

`bench/phase3.mjs` 在同一 Node 进程内交替测连续列与分块列；范围统计和积分各预热 3 次、计入 10 次，表中为中位数。追加行是**单次**跨倍增边界的计时，不能解释为稳定的 p50。精确性断言在计时过程中执行。

| 操作 | 规模 | 连续列 | 分块列 |
| --- | ---: | ---: | ---: |
| 范围统计 | 100 万点 | 9.6 ms | 14.0 ms |
| 范围统计 | 500 万点 | 54.0 ms | 77.5 ms |
| 能量积分 | 100 万点 | 7.8 ms | 11.4 ms |
| 能量积分 | 500 万点 | 33.8 ms | 41.6 ms |
| 11 列追加 5 万点（单次） | 从 100 万点起 | 39.7 ms | 8.8 ms |
| 11 列追加 25 万点（单次） | 从 500 万点起 | 188.4 ms | 25.1 ms |

| 11 列 Float64 缓冲区容量 | 连续列 | 分块列 |
| --- | ---: | ---: |
| 100 万点，追加前 | 88.0 MB | 88.3 MB |
| 100 万点，追加 5 万点后 | 176.0 MB | 92.6 MB |
| 500 万点，追加前 | 440.0 MB | 440.1 MB |
| 500 万点，追加 25 万点后 | 880.0 MB | 462.1 MB |

逻辑原始数据仍为每点 11 × 8 = 88 字节。分块避免整列搬运和容量翻倍，但每列最后一块最多预留 4095 个未用点，且块对象、索引、CSV 文本和应用其他数据另占内存。分块并未实现恒定内存录制。

补测 4095、4096、4097、10 万及 100 万点（范围扫描与积分各预热 2 次、计入 7 次）后，边界上的统计和积分结果与连续列逐项相同。4097 点刚跨块时，11 列分块容量为 720,896 B，连续列为 360,536 B；多出的约 360 KB 是新块暂未填满，原始点数并未增加。到 100 万点，追加前分块列与连续列分别为 88.31 MB 和 88.00 MB；再追加 5 万点后分别为 92.64 MB 和 176.00 MB。该次追加耗时为连续列 33.43 ms、分块列 4.35 ms；这仍只是一次跨扩容边界计时。新增原始记录为 `bench/results/performance-expanded-storage.json`。另以 10 次测量复核 100 万、200 万点范围扫描，分块列中位数分别为 13.74、27.92 ms，连续列为 9.48、19.34 ms，约慢 45%，原始记录为 `bench/results/performance-storage-confirm.json`。

## 模拟录制与数据完整性

正式构建产物通过有窗口 Edge + 模拟 Tauri 重放 100 Hz 原生批次：每 40 ms 发送 4 点，43 秒共 **4300 点**，跨过 4096 点块边界。发送数、消费数和末尾 seq 均为 4300；输入与 11 列输出 SHA-256 同为 `0d7d869bf28d8502af190c547a852d4046503128eae52c13b065ffa15c2c1b62`。录制中导出的 2152 点前缀校验通过，积分与实时累计完全一致，`streamErrors` 和 `capacityErrors` 均为 0。冻结历史窗口外另追加 80 点，主图提交/绘制为 0/0，导航图更新 20 次。

这次录制窗口被基准判为 `throttled`：有效帧供应不足，不能用其 rAF 或绘制间隔声明 FPS 提升。它证明的是这次模拟输入下的样本、序号、积分及导出完整性，不是真机 HID/WebView2 长时间验收。此前一次 43 秒尝试在 rAF 标定阶段退出，未开始采样；上述结果来自成功重试。

端到端浏览器对照中，100 万与 500 万点的图表顶点哈希和所有统计标量前后精确一致；10 万行 CSV 的 11 列导入哈希均与输入一致。跨块测试还覆盖录制段、NaN、负零、重复时间、边界和取消/失败路径。浏览器运行无 CSP 违规或运行时异常。

## 验证与限制

- 287 项 JavaScript 测试、typecheck、全库 lint、生产前端构建、`git diff --check` 通过；既有 `bench/core.mjs --compare` 三轮门禁通过，跟踪基线文件未改。
- 正式构建产物的 5 秒、500 点模拟录制也通过 hash、能量和 seq 校验。43 秒跨块录制的原始记录为 `bench/results/phase3-ui-boundary-retry.json`。
- CSV 仍一次读取整份文件文本；Rust 后台持久化、历史分页及 PD 后端百万条上限处理尚未实现。浏览器 heap 是运行后快照，不代表峰值；电源模式、温度和其他系统负载没有严格控制。

## 复现

```powershell
node bench/phase2-browser.mjs --dist bench/results/phase2-before/src --sizes 1000000,5000000 --csv-rows 100000 --runs 7 --warmup 2 --output bench/results/performance-overall-before.json
node bench/phase2-browser.mjs --dist src --sizes 1000000,5000000 --csv-rows 100000 --runs 7 --warmup 2 --output bench/results/performance-overall-after.json
node bench/phase2-browser.mjs --dist bench/results/phase2-before/src --sizes 10000,100000,1000000 --csv-rows 10000 --runs 5 --warmup 1 --output bench/results/performance-expanded-before.json
node bench/phase2-browser.mjs --dist src --sizes 10000,100000,1000000 --csv-rows 10000 --runs 5 --warmup 1 --output bench/results/performance-expanded-after.json
node bench/phase2-browser.mjs --dist bench/results/phase2-before/src --sizes 100000 --csv-rows 300000 --runs 5 --warmup 1 --output bench/results/performance-csv300k-before.json
node bench/phase2-browser.mjs --dist src --sizes 100000 --csv-rows 300000 --runs 5 --warmup 1 --output bench/results/performance-csv300k-after.json
node --expose-gc bench/phase3.mjs --sizes 1000000,5000000 --runs 10 --warmup 3 --output bench/results/phase3-final.json
node --expose-gc bench/phase3.mjs --sizes 4095,4096,4097,100000,1000000 --runs 7 --warmup 2 --output bench/results/performance-expanded-storage.json
node --expose-gc bench/phase3.mjs --sizes 1000000,2000000 --runs 10 --warmup 3 --output bench/results/performance-storage-confirm.json
npm run build:dist
node bench/ui-runner.mjs --dist out --shipped-csp --sizes 10000 --runs 1 --warmup 0 --duration 43 --emit-window-ms 40 --output bench/results/phase3-ui-boundary-retry.json
```

最后一条命令需要有窗口浏览器持续获得 rAF；若标定报帧数不足，录制尚未开始，不能当作失败的样本校验。原始 JSON 记录每次计时、哈希、资源清单、环境及异常。
